# ربط الميزان المباشر مع Axiom POS

أضيفت شاشة `/pos` لقراءة ميزان يرسل سطور وزن ASCII عبر منفذ تسلسلي USB/RS‑232. الشاشة تعرض وزن السلعة، تحسب وزن العبوة (tare) عند قراءة الوزن الإجمالي، وتعرض معاينة سعر الكيلو والسلة. تدعم غرام/كيلوغرام، وتقبل سطورًا مثل:

```text
ST,GS,+0.750 kg
ST,NT,750 g
0.750 kg
```

`ST` = ثابت، `US` = غير ثابت، `GS` = إجمالي، `NT` = صافي. إذا لم يرسل الجهاز علامة ثبات، تنتظر الشاشة ثلاث قراءات متقاربة. ترفض القراءات السالبة أو فوق سعة الجهاز أو القديمة؛ ولا تسمح بإعادة إضافة نفس الوزنة قبل ثلاث قراءات صفرية. الصنف يُختار من كتالوج المؤسسة، والسعر لا يأتي من الجهاز.

## الإعداد

1. طبّق الهجرة `0006_pos_live_scale.sql` بترتيب الهجرات: `pnpm db:migrate`.
2. أنشئ المؤسسة والعضوية وصندوق POS وصنف مخزون نشط وحدته الأساسية `KG` أو `KGM` وسعره موجب بدقة لا تتجاوز أربع منازل. يجب منح الدور `pos.scale.read` للقراءة و`pos.scale.configure` للإدارة. يحتاج المستخدم رمز JWT صالحًا؛ المستودع لا يحتوي بعد واجهة إصدار رمز للمستخدم.
3. أدخل معرّف المؤسسة والصندوق والرمز في شاشة `/pos` واضغط «تحميل الأصناف والإعدادات». لا يُخزن رمز الدخول في IndexedDB أو localStorage.
4. إذا أردت تخصيص المنفذ، استخدم `POST /api/v1/pos/terminals/:terminalId/serial-scale` مع `Authorization: Bearer ...` و`x-organization-id: ...`:

```json
{
  "baudRate": 9600,
  "dataBits": 8,
  "stopBits": 1,
  "parity": "none",
  "flowControl": "none",
  "defaultUnit": "kg",
  "readingKind": "gross",
  "toleranceKg": "0.0020",
  "maxWeightKg": "60.0000",
  "maxAgeMs": 2000
}
```

5. فعّل صنف الكيلو مع وزن العبوة من `POST /api/v1/pos/terminals/:terminalId/weighable-products`:

```json
{ "productId": "UUID-OF-PRODUCT", "tareWeight": "0.0250", "isActive": true }
```

6. افتح POS في Chrome أو Edge على كمبيوتر الصندوق عبر HTTPS أو `localhost`، واضغط «اختيار منفذ الميزان» واختر منفذ الجهاز. يمكن تغيير السرعة والوحدة مؤقتًا من الشاشة قبل الاتصال. **الوحدة الافتراضية تطبق فقط عندما لا يرسل الجهاز الوحدة داخل السطر.**

اختبر وزنًا معياريًا معروفًا على نفس الجهاز ثم اختبر وزن العبوة؛ يلزم اسم موديل الميزان أو عينة من بيانات المنفذ الفعلية لإضافة بروتوكول خاص. أجهزة HID/USB التي لا تظهر كمنفذ تسلسلي تحتاج موصلًا مختلفًا. قراءة الميزان تعتمد على إذن المستخدم من المتصفح ولا تتطلب كشف المنفذ لخادم ERP. راجع [MDN Web Serial](https://developer.mozilla.org/en-US/docs/Web/API/Web_Serial_API) لدعم المتصفح وشروط السياق الآمن.

## حدود النسخة الحالية

هذه **معاينة محلية** وليست بيعًا معتمدًا. لا يصدر التطبيق فاتورة أو يقيد مخزونًا أو يسجل قيدًا ماليًا عند إضافة الوزنة؛ مسار `POST /pos/devices/:id/sync` وخدمة ترحيل البيع إلى نواة المخزون والمحاسبة غير منفذين في المستودع الأصلي. يجب إنجاز ترحيل ذرّي ومراجعة سعر ومخزون الخادم واختبارات عكس القيود قبل إتاحة زر الدفع. لا تستخدم مجموع المعاينة لتحصيل أموال الزبائن.
# ملصق الميزان المطبوع

إذا كان الميزان يطبع ملصقًا لاصقًا، يكفي قارئ باركود USB يعمل كلوحة مفاتيح، أو إدخال الرقم يدويًا في حقل **مسح ملصق الميزان** ثم Enter. لا يحتاج هذا المسار توصيل الميزان بمنفذ Serial. حمّل الصندوق والأصناف أولًا؛ تستخدم الشاشة نقطة `GET /api/v1/pos/terminals/:terminalId/scale-config` الموجودة أصلًا في المشروع.

الملصق المصوَّر يقرأ `2000001002001`، ويُقسّم إلى `2` + رقم الصنف `000001` + وزن `00200` غرام + رقم تحقق `1`. رقم التحقق صالح وفق EAN-13. وزنه 0.200 كغ × 5.000 د.أ/كغ = 1.000 د.أ كما على الملصق. أضف ملفًا إلى الصندوق عبر `POST /api/v1/pos/terminals/:terminalId/scale-profiles` بالجسم `{"code":"STORE_LABEL","name":"ملصق الميزان","preset":"EAN13_WEIGHT_2_PLU6"}` ثم اربط `PLU` = `000001` بمعرّف الصنف عبر `POST /api/v1/pos/scale-profiles/:profileId/mappings` بالجسم `{"plu":"000001","productId":"<product UUID>","tareWeight":"0"}`. يجب أن يكون سعر كيلو هذا الصنف 5.000 في كتالوج الاختبار ليتطابق الإجمالي. إعداد العينة يعتمد على ملصق واحد؛ اختبر ملصقات منتجات وأوزان أخرى قبل التشغيل الفعلي.

تتحقق الشاشة من رقم EAN-13، وتطرح وزن العبوة المحدد في ربط PLU، وتسعّر الوزن الصافي وفق سعر الصنف في الكتالوج، وتمنع إضافة نفس رقم الملصق مرتين في السلة. الملصق الذي يحمل **السعر فقط** دون الوزن لا يُضاف، لأن استنتاج كمية المخزون من السعر المقرب قد يعطي كمية خاطئة. ما تزال السلة معاينة محلية بلا إصدار فاتورة أو حركة مخزون.
